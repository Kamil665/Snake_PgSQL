🐍 База данных игры «Змейка»
Описание проекта

База данных предназначена для хранения информации об игроках, результатах игр и сохранённых состояниях игры «Змейка».

Используется реляционная система управления базами данных PostgreSQL. Для хранения координат тела змейки и положения яблока применяется формат JSONB.

Структура базы данных

База данных состоит из трёх таблиц:

users — информация о пользователях.
scores — результаты сыгранных партий.
game_saves — сохранённое состояние игры.
1. Таблица users

Хранит информацию о зарегистрированных пользователях.

Поле	Тип данных	Описание
id	BIGSERIAL	Первичный ключ
username	VARCHAR(50)	Уникальное имя пользователя
email	VARCHAR(255)	Электронная почта
created_at	TIMESTAMPTZ	Дата регистрации

Особенности:

id — автоматически генерируемый идентификатор.
username — обязательное уникальное поле.
email — уникальное поле, допускает NULL.
created_at — по умолчанию устанавливается текущее время.

Создан индекс idx_users_username для ускорения поиска пользователей по имени.

2. Таблица scores

Хранит результаты завершённых игровых партий.

Поле	Тип данных	Описание
id	BIGSERIAL	Первичный ключ
user_id	BIGINT	Идентификатор пользователя
score	INT	Количество набранных очков
snake_length	INT	Длина змейки
duration_interval	INTERVAL	Продолжительность игры
played_at	TIMESTAMPTZ	Дата и время игры

Особенности:

user_id связан с таблицей users через внешний ключ.
При удалении пользователя его результаты также удаляются (ON DELETE CASCADE).
score не может быть отрицательным.
snake_length должен быть больше нуля.
По умолчанию счёт равен 0, длина змейки — 1.

Создан индекс idx_scores_top для ускорения получения лучших результатов с сортировкой по очкам и времени игры.

3. Таблица game_saves

Хранит текущее состояние игры пользователя.

Поле	Тип данных	Описание
user_id	BIGINT	Идентификатор пользователя
snake_body	JSONB	Координаты сегментов змейки
apple_pos	JSONB	Координаты яблока
direction	VARCHAR(5)	Направление движения
current_score	INT	Текущий счёт
updated_at	TIMESTAMPTZ	Время последнего обновления

Особенности:

user_id является первичным и внешним ключом.
Для одного пользователя хранится одно сохранение.
snake_body и apple_pos хранятся в формате JSONB.
Допустимые направления: UP, DOWN, LEFT, RIGHT.
При удалении пользователя его сохранение также удаляется.
updated_at автоматически получает текущее время при создании записи.
Связи между таблицами
users → scores: связь один ко многим (1:N).
users → game_saves: связь один к одному (1:1).

При удалении пользователя автоматически удаляются связанные с ним результаты и сохранение игры.

Используемые технологии
PostgreSQL — система управления базами данных.
BIGSERIAL — автоматическая генерация идентификаторов.
JSONB — хранение координат змейки и яблока.
TIMESTAMP WITH TIME ZONE — хранение даты и времени с учётом часового пояса.
INTERVAL — хранение продолжительности игровой партии.
CHECK — проверка допустимых значений.
FOREIGN KEY — обеспечение целостности связей между таблицами.
Установка и запуск
Установите PostgreSQL.
Создайте базу данных:
sql
CREATE DATABASE snake_game;

Подключитесь к созданной базе данных:
bash
psql -U postgres -d snake_game

Выполните SQL-скрипт создания таблиц и индексов.
Пример данных

Добавление пользователя:

sql
INSERT INTO users (username, email)
VALUES ('player1', 'player1@example.com');


Добавление результата игры:

sql
INSERT INTO scores (user_id, score, snake_length, duration_interval)
VALUES (1, 100, 10, INTERVAL '2 minutes 30 seconds');


Сохранение состояния игры:

sql
INSERT INTO game_saves (
    user_id,
    snake_body,
    apple_pos,
    direction,
    current_score
)
VALUES (
    1,
    '[{"x":5,"y":5},{"x":4,"y":5},{"x":3,"y":5}]',
    '{"x":10,"y":8}',
    'RIGHT',
    100
);

Получение таблицы лидеров

Пример SQL-запроса для получения десяти лучших результатов:

sql
SELECT
    u.username,
    s.score,
    s.snake_length,
    s.duration_interval,
    s.played_at
FROM scores s
JOIN users u ON u.id = s.user_id
ORDER BY s.score DESC, s.played_at DESC
LIMIT 10;

Назначение базы данных

База данных обеспечивает:

регистрацию и хранение информации об игроках;
сохранение результатов игровых партий;
формирование таблицы лидеров;
сохранение текущего состояния игры;
восстановление игры после выхода пользователя.
