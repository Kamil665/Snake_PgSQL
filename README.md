# 🐍 База данных игры «Змейка»

## 📌 Описание проекта

Проект представляет собой реляционную базу данных для игры **«Змейка»**, разработанную с использованием PostgreSQL.

База данных предназначена для хранения информации об игроках, результатах игровых сессий и текущем состоянии игры. Она позволяет вести таблицу рекордов и сохранять прогресс игрока для последующего продолжения игры.

## 🛠 Используемые технологии

- **PostgreSQL** — система управления базами данных.
- **SQL** — язык создания и управления данными.
- **JSONB** — хранение координат тела змейки и положения яблока.

## 🗄 Структура базы данных

База данных состоит из трёх основных таблиц:

### 1. `users` — пользователи

Хранит информацию об игроках.

| Поле | Тип данных | Описание |
|---|---|---|
| id | BIGSERIAL | Уникальный идентификатор |
| username | VARCHAR(50) | Имя пользователя |
| email | VARCHAR(255) | Электронная почта |
| created_at | TIMESTAMPTZ | Дата регистрации |

Особенности:
- `id` — первичный ключ.
- `username` — уникальное имя пользователя.
- `email` — уникальный адрес электронной почты.

### 2. `scores` — результаты игр

Хранит результаты завершённых игровых сессий.

| Поле | Тип данных | Описание |
|---|---|---|
| id | BIGSERIAL | Идентификатор результата |
| user_id | BIGINT | ID пользователя |
| score | INT | Количество очков |
| snake_length | INT | Длина змейки |
| duration_interval | INTERVAL | Продолжительность игры |
| played_at | TIMESTAMPTZ | Дата игры |

Особенности:
- Связь с таблицей `users` через внешний ключ.
- При удалении пользователя его результаты также удаляются.
- Очки не могут быть отрицательными.
- Длина змейки должна быть больше нуля.

### 3. `game_saves` — сохранения игры

Хранит текущее состояние игры пользователя.

| Поле | Тип данных | Описание |
|---|---|---|
| user_id | BIGINT | ID пользователя |
| snake_body | JSONB | Координаты тела змейки |
| apple_pos | JSONB | Положение яблока |
| direction | VARCHAR(5) | Направление движения |
| current_score | INT | Текущие очки |
| updated_at | TIMESTAMPTZ | Время последнего сохранения |

Допустимые направления:
- `UP` — вверх.
- `DOWN` — вниз.
- `LEFT` — влево.
- `RIGHT` — вправо.

Для каждого пользователя предусмотрено одно сохранение игры.

## 🔗 Связи между таблицами

- `users` → `scores` — связь один ко многим (1:N).
- `users` → `game_saves` — связь один к одному (1:1).

При удалении пользователя автоматически удаляются связанные результаты и сохранение игры благодаря `ON DELETE CASCADE`.

## ⚙️ Индексы

Для ускорения поиска и сортировки созданы индексы:

- `idx_users_username` — поиск пользователей по имени.
- `idx_scores_top` — получение лучших результатов с сортировкой по очкам и дате игры.

## 🚀 Установка и запуск

1. Установите PostgreSQL.
2. Создайте новую базу данных:

```sql
CREATE DATABASE snake_game;
```

3. Подключитесь к базе данных:

```sql
\c snake_game
```

4. Выполните SQL-скрипт создания таблиц и индексов.

## 💻 Примеры SQL-запросов

### Добавление пользователя

```sql
INSERT INTO users (username, email)
VALUES ('Kamil', 'kamil@example.com');
```

### Добавление результата игры

```sql
INSERT INTO scores (user_id, score, snake_length, duration_interval)
VALUES (1, 150, 8, INTERVAL '2 minutes');
```

### Просмотр таблицы рекордов

```sql
SELECT
    u.username,
    s.score,
    s.snake_length,
    s.played_at
FROM scores s
JOIN users u ON s.user_id = u.id
ORDER BY s.score DESC, s.played_at DESC
LIMIT 10;
```

### Просмотр всех пользователей

```sql
SELECT * FROM users;
```

### Просмотр сохранений

```sql
SELECT * FROM game_saves;
```

## 🎯 Цель проекта

Создать надёжную структуру базы данных для игры «Змейка», обеспечивающую:

- Регистрацию и хранение пользователей.
- Сохранение результатов игровых сессий.
- Формирование таблицы рекордов.
- Сохранение текущего состояния игры.
- Возможность продолжения игры с последнего сохранения.
